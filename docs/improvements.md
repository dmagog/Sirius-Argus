# План доработок (backlog)

Отложенные улучшения и честные остатки. Заводится по ходу, чтобы не терять контекст.
Формат: приоритет · что · зачем/контекст.

## UI / дизайн (приложение «Обзор контура» `/map`)
- **P1 · Глобальная тема.** Светлые токены (`[data-sa-theme=light]`) и переключатель сейчас живут только в шелле `/map` (это и есть макет из хэндоффа). Остальные разделы (`/dashboard`, `/registry`, `/findings`, `/coverage`, `/serving`, `/services`, `/roles`) — на старом `layout.py`, только тёмные. Вынести светлые токены + переключатель в общий `layout._THEME`, чтобы приложение переключалось разом и тема была сквозной.
- **P2 · Заполнение графа.** Масштабируемый слой (`Scaled`, `W=1432`) под разные ширины оставляет немного пустого места по краям; дополировать пропорции/высоту под широкие и узкие экраны.
- **P3 · Accent-палитра.** В хэндофф-Tweaks была смена акцента (`#facc15/#fb923c/#38bdf8`). В прод не несли (демо-обвязка). Низкий приоритет — добавить, если попросят.

## Данные «прогоны» / lineage (`runs.py`)
- **P2 · Тайминг прогона.** У `ModelVersion` нет `created_at`/timestamps, поэтому `start`/`dur` в карточке прогона частично псевдо (`dur` — детерминированная заглушка). Добавить таймстемпы версии (created/promoted/retired) для настоящего тайминга и длительности.
- **P2 · Привязка findings ингеста к версии.** Findings ингест-гейта пишутся с `asset_ref='model/<id>'` (без версии), а версионные — `model/<id>/v<n>`. Сейчас model-scoped относим к самой свежей версии (эвристика). Чисто: писать в `ingest_model` `asset_ref=f"model/<id>/v<n>"`, тогда эвристику убрать.

## Безопасность / прод-готовность
- **P1 · Роль причастного в проде.** `Finding.actor` хранит только субъект (`p.sub`); в demo это username (ds→DS надёжно), в проде Keycloak — UUID, и роль на сработке не сохраняется. Резолв роли в проде ненадёжен. Решение: добавить поле роли в `Finding` при создании (брать из `Principal.roles`) — тогда «кто причастен» точен и в проде.
- **P3 · MinIO console-SSO.** Community-образ `RELEASE.2025-09` вырезал OIDC-вход в консоль (только S3-STS). Опции: пин старого образа ради console-SSO (риск совместимости) либо принять root-вход в консоль (текущее, задокументировано в ADR-0012).

## Функциональность (UI-действия)
- **P1 · Кнопки HITL-аппрува.** На этапе ручного аппрува (HITL) в интерфейсе должна быть реальная кнопка «Аппрув / Отклонить» — сейчас аппрув только через API. Добавить действие там, где прогон ждёт HITL (инспектор прогона при `state=hitl` / страница промоушена): аппрув с обоснованием и separation of duties (аппрувер ≠ владелец), отклонение, запись в `Approval` + аудит, обновление состояния прогона.
