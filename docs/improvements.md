## UI / дизайн (сквозной вид приложения)
- **✅ P1 · Сквозной навигационный каркас (боковое меню).** _Сделано._ Общий sidebar `layout._page` приведён к виду SA-рейла: пункты разделов получили те же Bootstrap-иконки, что и рейл `/map` (`_NAV_ICON`), с акцентом иконки на hover/active; ширина/hover/active/подвал — на `--sa-*` токенах. Первый уровень навигации идентичен с пайплайном; контекст пайплайна (узлы конвейера/инфры) остаётся только внутри `/map`.
- **✅ P1 · Глобальная тема.** _Сделано._ Светлые токены (`[data-sa-theme=light]`) и переключатель вынесены в общий `layout` (тот же localStorage-ключ `'sa-theme'`, что и `/map`) — тема переключается разом и сквозная по всем разделам. Init-скрипт в `<head>` применяет сохранённую тему до отрисовки (без мигания); кнопка темы — в подвале сайдбара; KPI/hover таблиц переведены на токены для корректной перекраски.
- **✅ P2 · Заполнение графа.** _Сделано._ Слой масштабировался только по ширине (`scale(w/1432)`), а высота бокса была фиксированной 392 — на не-1432 ширинах контент короче бокса (пустота снизу), на широких — обрезался. `fit()` теперь задаёт высоту графа = `392·scale` (идемпотентно, без петли ResizeObserver): бокс хугает масштабированный контент на любой ширине. Финальную пиксельную полировку лучше глянуть на пересборке вживую.
- **✅ P3 · Accent-палитра.** _Сделано (по запросу)._ Пикер акцента из 3 свотчей (золото `#facc15` по умолчанию / оранжевый `#fb923c` / голубой `#38bdf8`) рядом с переключателем темы в обоих шеллах: топбар `/map` и подвал глобального сайдбара. Сквозной через `localStorage 'sa-accent'`; `saAccent` правит `--sa-accent`/`--sa-accent-ink` (и легаси `--accent` в глобальном шелле); пре-рендер-скрипт применяет выбор до отрисовки (без мигания); выбор «золото» снимает override и возвращает тему-зависимый дефолт. По образцу переключателя темы.
- **✅ P3 · Hero-сплэш при загрузке (wow-эффект для защиты).** _Сделано._ Оверлей `.sa-splash` на стартовом экране (обзор `/map`): крупный логотип в золотом ореоле + бренд + декоративный прогрессбар (`saSplashBar` 0→100% за ~0.82с), затем плавный fade-out (~1.05с суммарно) и удаление из DOM. Чистый CSS/JS без зависимостей; фон `var(--sa-bg)` + тема применяется до отрисовки (без мигания); показывается **один раз за сессию** (`sessionStorage 'sa-splash-seen'`, не мозолит при навигации); уважает `prefers-reduced-motion` (без анимации, короткий показ); только на обзоре (в инспекторе нет); оверлей поверх готового server-rendered контента — загрузку не блокирует. Финальную пиксельную полировку — на пересборке вживую.

## Данные «прогоны» / lineage (`runs.py`)
- **✅ P2 · Тайминг прогона.** _Сделано._ У `ModelVersion` появились `created_at`/`promoted_at`/`retired_at` (ISO-UTC), проставляются при создании/ингесте/промоушене/выводе. `runs._duration` считает настоящую длительность `created → (promoted|retired|сейчас)` с адаптивным форматом (`MM:SS` / `Nч MMм` / `Nд Hч`); `start`/`dur` в карточке прогона теперь реальные, для легаси-версий без `created_at` — честный псевдо-fallback. Инспектор показывает строку «заведён · в проде · выведен · в контуре». Аддитивная idempotent-миграция трёх колонок.
- **✅ P2 · Привязка findings ингеста к версии.** _Сделано (+ исправление корректности)._ `ingest_model` теперь пишет findings **admitted**-артефакта с версионным `asset_ref='model/<id>/v<n>'` (привязка к создаваемой версии). Findings **заблокированного** ингеста (вредоносный артефакт — версия не создаётся, слот номера переиспользуется) остаются model-scoped `model/<id>` как «отклонённая попытка»: видны в журнале/на гейте/в coverage, но намеренно не относятся ни к одному прогону. Эвристику-вакуум (model-scoped → самая свежая версия) в `runs.py` убрал — `_version_findings`/`run_detail` собирают строго по `model/<id>/v<n>`. Побочно исправлена протечка: раньше блокированная вредоносная сработка ошибочно показывалась в инспекторе свежей версии — теперь нет.

## Безопасность / прод-готовность
- **✅ P1 · Роль причастного в проде.** _Сделано._ `Finding` получил поле `role` — заполняется на всех точках создания из `Principal.roles` через `auth.primary_role()` (одна «основная» роль по приоритету; системные пути — `Service`/пусто). Отображение «причастен» теперь через `runs.role_of`: предпочитает сохранённую роль (надёжно и в проде, где `actor` — UUID Keycloak), а для легаси-записей без роли — fallback на прежнюю эвристику `actor_role`. Роль прокинута в read-back (`/api/findings`, журнал, инспектор, инцидент). Аддитивная idempotent-миграция `findings.role`. Остаётся аналогичный зазор по роли аппрувера в `Approval` (в проде sub = UUID) — при желании вынести отдельным пунктом.
- **✅ P3 · Роль аппрувера в `Approval`.** _Сделано (по аналогии с `Finding.role`)._ `Approval.role` пишется при решении: API approve/reject — `p.primary_role()`, UI-инспектор — `MLSecOps` (аппруверы валидированы как MLSecOps-учётки). Журнал решений (`_decision_block`) предпочитает сохранённую роль, для легаси-решений без роли — fallback на эвристику `actor_role`. Надёжно и в проде, где `approver` — UUID Keycloak. Аддитивная миграция `approvals.role`; роль добавлена и в `/review`-бандл.
- **P3 · MinIO console-SSO.** Community-образ `RELEASE.2025-09` вырезал OIDC-вход в консоль (только S3-STS). Опции: пин старого образа ради console-SSO (риск совместимости) либо принять root-вход в консоль (текущее, задокументировано в ADR-0012).

## Логика / семантика
- **✅ P2 · Статус узла vs здоровье потока.** _Сделано (развели понятия, без пропагации)._ Решение: цвет узла намеренно про «здоровье узла» (его собственные открытые findings через `node_of`), а не про прохождение потока — пропагировать проблемы вниз по потоку было бы неверно (красный гейт не делает «Вывод» больным). Двусмысленность снята явными подписями: на обзоре — легенда «цвет узла = здоровье узла (его сработки) · линия/частицы = поток ЖЦ · здоровье узла независимо от потока: зелёный узел ниже ≠ прогон прошёл гейты чисто»; в инспекторе — шапка показывает «здоровье узла: чисто / ● N откр.» с пояснением независимости от потока, а над очередью — «трек = прохождение прогона по потоку, бейдж = состояние прогона». Движение конкретного прогона (`blocked` на гейте) видно в его карточке/треке, отдельно от здоровья узлов.

## Функциональность (UI-действия)
- **✅ P1 · Кнопки HITL-аппрува.** _Сделано._ В инспекторе прогона (`/map/node/*`) для критичной версии (`requires_validation`) появилась панель «Требует решения (HITL)»: доказательный чеклист «почему требует внимания» (зеркалит гейт promote — модель-карта GOV-01, воспроизводимость MON-02, подпись SUP-04, нет открытых critical, аппрув другим MLSecOps VIS-03/ACC-02), журнал принятых решений и кнопки **Аппрув / Отклонить** с обоснованием (для reject — обязательным). Действие пишет `Approval` (поле `decision`, привязка к `artifact_hash`) + аудит (`model.approve`/`model.reject`) общим кодом `decisions.record_decision`, обновляет состояние прогона (`hitl→hold` / `→rejected`) без перезагрузки страницы. Отклонение имеет «зубы»: `promote` блокируется (`promote.blocked.rejected`), пока решение не сменит новый аппрув по тому же артефакту. Separation of duties (аппрувер ≠ владелец, аппрувер ≠ промоутер) энфорсится на промоушене. Reject-эндпоинт добавлен и в публичный API (`POST /api/models/{id}/versions/{v}/reject`).
