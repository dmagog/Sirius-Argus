# Рунбук: временный публичный демо-стенд на NetAngels

Развёртывание профиля **core** на одном облачном сервере с Docker, под доменом, с TLS и
демоданными. Рассчитано на короткий срок (демо + буфер, ~неделя) с последующим сносом.

> **Область применения.** Это рецепт ДЕМО-стенда, не боевого деплоя. Здесь сознательные упрощения
> ради быстрого показа: `DEV_AUTH`-сид демоданных, Vault в dev-режиме и сервер Keycloak в `start-dev`
> (realm при этом — прод, `infra/keycloak-prod`, без персон), общий Basic-Auth
> (или открытый периметр — см. «Заметки безопасности»), без бэкапов.
> Всё демо-специфичное — в overlay-файлах `docker-compose.prod.yml` / `docker-compose.seed.yml`;
> базовый `docker-compose.yml` не затрагивается. **Боевой контур — другой режим** (реальный OIDC/SSO
> для UI, Vault с unseal и персистентностью, Keycloak в prod, внешний секрет-стор и ротация, бэкапы,
> мониторинг) — компромиссы отсюда туда не переносить.

## Что это даёт

- Единая точка входа `https://<домен>` за HTTP Basic Auth (общий логин для жюри).
- Засеянные демоданные: money-shot'ы платформы и критичная модель `fraud-scoring`,
  оставленная **в ожидании ручного аппрув-гейта** — для живого клика «Аппрув» на демо.
- `/api` заперт (`DEV_AUTH=0`): подделать `dev:*`-токен и дёрнуть ingest/promote/offboard нельзя.
- Наружу открыты только 80/443 (Caddy) и 22 (SSH). serving и веб-консоль MinIO — только локально.

## Предпосылки

1. **Сервер**: облачный сервер NetAngels, рекомендую 6 ГБ RAM / 2 vCPU / 40 ГБ SSD
   (Keycloak на JVM + сборка образов numpy/sklearn). Минимум — 4 ГБ, но без запаса.
2. **ОС + Docker**: Ubuntu 22.04/24.04, `docker` + `docker compose` v2.24+, `python3`, `openssl`.
   Если Docker нет:
   ```
   curl -fsSL https://get.docker.com | sh
   apt-get install -y python3
   ```
3. **DNS**: A-запись `<домен>` → IP сервера. Дождаться распространения (`dig +short <домен>`).
4. **Порт 80/443** должны быть достижимы извне для выпуска сертификата Let's Encrypt.

## Развёртывание

```bash
# 1. Код на сервере (репозиторий публичный)
git clone https://github.com/dmagog/Sirius-Argus.git
cd Sirius-Argus            # каталог secure-mlops-platform, если клонируешь монорепо

# 2. Один прогон: генерит .env.prod, засевает данные, запирает /api, делает префлайт
PUBLIC_HOST=<домен> DEMO_PASS='<пароль-для-жюри>' bash scripts/deploy_netangels.sh

# 3. Файрвол (22 — ДО enable, чтобы не отрезать SSH)
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
#   либо: DO_FIREWALL=1 ... bash scripts/deploy_netangels.sh
```

Скрипт сам:
- сгенерит стойкие секреты и bcrypt-хэш demo-пароля в `.env.prod` (права 600, не коммитится);
- поднимет стек с `DEV_AUTH=1` на 127.0.0.1, прогонит `scripts/demo.py` (засев);
- пересоздаст control-plane с `DEV_AUTH=0` и снимет локальные порты;
- проверит, что dev-токен на `/api` теперь отдаёт **401** (иначе остановится и не откроет периметр).

## Что показывать на демо

1. Открыть `https://<домен>` → если периметр за Basic Auth, ввести `demo` / выданный пароль (в открытом варианте — см. «Заметки безопасности» — формы нет, сразу `/map`).
2. `/map` — карта контура и покрытие угроз; `/coverage` — KPI-вью; `/dashboard` — live-сработки и аудит.
3. **HITL**: на `/map` найти узел `fraud-scoring` (criticality `regulatory`, статус «ожидает аппрува»)
   → открыть инспектор → **Аппрув**, выбрать approver `mlsecops` (или `reject` с причиной).
   Решение пишется в аудит (append-only, hash-chain) и видно в таймлайне.
4. Вход Keycloak-персонами на демо-стенде не используется: UI закрыт общим Basic Auth, а
   прод-realm (`infra/keycloak-prod`) персон не содержит. Персоны `ds`, `de`, `mlsecops`,
   `product`, `ceo` (пароль = логин) есть только в локальном dev-стеке (`make up`).

## Доступ к закрытым консолям (по желанию)

```bash
ssh -L 9001:127.0.0.1:9001 <user>@<домен>     # затем http://localhost:9001 — веб-консоль MinIO
```

## Снос (по окончании)

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml down -v   # +удалить тома с данными
```
Затем погасить/удалить сам сервер в панели NetAngels (почасовая тарификация — платим только за срок).

## Заметки безопасности (осознанные компромиссы демо-стенда)

- **Периметр (дефолт — Basic Auth на Caddy).** UI control-plane намеренно без собственного логина,
  поэтому весь периметр закрывается общим Basic Auth — это «минимально-безопасный» дефолт для
  любого публичного выноса. Жёстче: заменить `basic_auth` в `Caddyfile.prod` на `remote_ip`-allowlist
  или поднять реальный OIDC-вход для UI.
  - *Только для короткого одноразового публичного демо* периметр можно **полностью открыть**
    (убрать `basic_auth` из `Caddyfile.prod` → зритель сразу в контуре, без формы). Цена: единственный
    login-less пишущий роут — аппрув-гейт `/ui/map/run/...` — становится публично кликабельным
    (в прод не промоутит — это `/api` под `DEV_AUTH=0`; pending-гейт при нужде пере-армить).
    **Для общего/долгого деплоя так НЕ делать.**
  - Готча: после правки `Caddyfile.prod` нужен `docker compose … up -d --force-recreate reverse-proxy`,
    а не `caddy reload` — замену bind-mount'нутого одного файла Caddy не подхватит (контейнер держит старый inode).
- Vault — в dev-режиме, сервер Keycloak запущен в `start-dev` (воспроизводимость). Realm при этом
  на публичном контуре — прод (`infra/keycloak-prod`: `bruteForceProtected`, ROPC выключен, без персон),
  а не dev-realm с демо-персонами. При **перезагрузке сервера** Vault теряет
  засеянные секреты; восстановить — повторным прогоном `deploy_netangels.sh`. На неделю демо ребут не планировать.
- Публичный стенд использует прод-realm (`infra/keycloak-prod`), персон в нём нет. Тривиальные
  демо-пароли (логин = пароль) остались только в локальном dev-realm. Админские/инфраструктурные
  секреты на стенде ротируются скриптом.
- `.env.prod` содержит все секреты стенда — хранить с правами 600, не коммитить, удалить при сносе.
