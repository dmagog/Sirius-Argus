# Sirius Argus — Реагирование на инциденты и восстановление (IR & DR)

> Закрывает пробел «перекос prevention/detection над response/recovery». Детект — это половина MLSecOps; вторая — реакция и восстановление. Скелет рунбука: уточняется по мере роста системы.

## Классификация severity

| Severity | Критерий | Примеры (Finding) | Реакция |
|---|---|---|---|
| **SEV1** | компрометация контура контроля / прод-данных | CP-1, ML-1, GT-2, audit-tamper, секрет в проде | немедленно, роль MLSecOps + Platform |
| **SEV2** | заблокированная атака / высокий риск | вредоносный артефакт, CVE-PR, extraction-бёрст | в течение часа, MLSecOps |
| **SEV3** | низкий риск / возможный фолз | единичный adversarial-инпут, дрейф-предупреждение | планово, триаж |

## Жизненный цикл инцидента

`Detect → Triage → Contain → Eradicate → Recover → Post-mortem`

1. **Detect** — автодетект (CI-гейт / runtime-детектор) порождает `Finding` + запись в таймлайн.
2. **Triage** — роль IR/MLSecOps подтверждает TP/FP (риск VIS-04: смена статуса — только с правами и в аудит).
3. **Contain** — изоляция: блок промоушена, отзыв токена, снятие endpoint, карантин артефакта/датасета.
4. **Eradicate** — устранение причины (патч зависимости, отзыв доступа, удаление вредоносного артефакта).
5. **Recover** — восстановление из доверенного состояния (см. DR ниже), ре-верификация подписи и гейтов.
6. **Post-mortem** — разбор без поиска виноватых, запись урока в базу (предотвращает повтор).

## Плейбуки (по топ-сценариям)

- **Вредоносный артефакт (SUP-01):** артефакт уже заблокирован до загрузки → подтвердить, занести источник в недоверенные, проверить, не пришёл ли он другими путями.
- **Компрометация CI (CI-01 / GT-2, SEV1):** заморозить пайплайн, ротировать раннер-токены, проверить пины образов, пересобрать из доверенного состояния.
- **Тамперинг реестра (REG-01 / ML-1, SEV1):** сверить метаданные с integrity-эталоном, откатить флаги, ротировать креды MLflow, проверить netpolicy.
- **Утечка секрета (SECR-1):** немедленная ротация секрета, чистка истории, аудит использования.
- **Extraction-бёрст (RT-01):** усилить rate-limit/квоту по ключу, оценить объём утёкших ответов, при необходимости отозвать ключ.
- **Компрометация Keycloak (KC-1, SEV1):** инвалидировать сессии и выданные токены, ротировать ключи realm и client-secrets, проверить аудит на действия под захваченными identity; до восстановления — fail-closed (AUTH-01).
- **Подделка событий в шине (BUS-1):** отозвать креды клиента шины, сверить критичные события с tamper-evident аудитом (он независим), при расхождении — приоритет аудиту.

## Доступность и восстановление (DR)

Триада CIA: доступность — не «по остаточному принципу».

| Актив | Бэкап | RPO (цель) | RTO (цель) |
|---|---|---|---|
| Метаданные (Postgres: реестр, audit, findings) | регулярный дамп | ≤ 1 ч | ≤ 1 ч |
| Артефакты/датасеты (MinIO) | версионирование по хешу + копия | ≤ 24 ч | ≤ 4 ч |
| Конфиг/IaC (`docker-compose`, CI, политики) | в git (этот репо) | 0 (в VCS) | ≤ 30 мин |

- **Воспроизводимость как DR:** каждая прод-модель имеет зафиксированные code+data+env (MON-02) — это и есть план «перевывести, если всё упало» (закрывает «DS ушёл — некому перевывести»).
- **Целостность аудита** при восстановлении: hash-chain позволяет убедиться, что восстановленная история не подменена (MON-04).
- Регулярная проверка восстановления (restore drill) — иначе бэкап не бэкап.
