# Sirius Argus — Персоны угроз и защиты (perspective-driven)

> Назначение: посмотреть на платформу глазами тех, кто на неё нападает, и тех, кто её защищает. Для каждой персоны — цель, поверхность, шаги, контроль Sirius Argus и **BDD-сценарии**, доказывающие покрытие. Источник полноты [BDD-каталога](bdd-catalog.md) и [реестра рисков](risk-register.md).
>
> Все «роли» здесь — adversary-персоны и системные RBAC-акторы, **не члены команды**. У каждой есть кодовое имя «в кавычках» — для удобства обсуждения («Крот», а не «A7»).

> **Ключевой принцип охвата:** моделируем не только атаки на ML-активы (данные, модель, инференс), но и атаки на **сам контур контроля** — CI/build, control-plane, реестр, сеть. Если скомпрометирован энфорсер гейтов, все «зелёные» проверки становятся ложью, поэтому этот класс вынесен явно (A12–A22).

## 2. Взгляд атакующего на систему

**ML-активы:**
- **A1.** Стучится в открытые порты, ищет неаутентифицированные эндпоинты и старые CVE. → authN на всех маршрутах, MLflow/MinIO не наружу, валидация входа. → `ACC-05`, `RT-05`.
- **A2.** Через inference API выкачивает скоры (extraction), восстанавливает членство/признаки. → rate-limit, extraction-detect, output reduction. → `RT-01`, `RT-03`, `RT-04`.
- **A3.** Подсовывает модель с pickle-RCE, тайпсквоттит пакет, прячет бэкдор в «безопасном» формате. → скан до десериализации, allow-list/скан, подпись; ShadowLogic — остаточный. → `SUP-01`, `SUP-02`, `SUP-04`, `SUP-06`.
- **A4.** Крафтит adversarial-входы, прощупывает границу решения. → детект adversarial/FGSM, дрейф, ART. → `RT-02`, `MON-01`.
- **A5.** Заливает отравленные данные/триггер через UGC. → trusted-sources, карантин, проверки качества. → `DATA-01`, `DATA-03`.
- **A6.** Цепочка CVE→traversal→перезапись артефакта→RCE→C2; заметает следы. → integrity артефактов, изоляция, hash-chain аудит. → `SUP-05`, `MON-04`, `RT-06`.
- **A7.** Сам себе одобряет критичную модель, зашивает бизнес-логику-бэкдор, тащит данные. → RBAC, разделение полномочий, policy/review, аудит. → `ACC-01`, `ACC-02`, `ACC-04`, `ACC-07`.
- **A8.** Коммитит секрет, тянет старую либу, оставляет PII, не фиксирует окружение. → gitleaks, скан в CI, маскирование, гейт воспроизводимости. → `ACC-06`, `SUP-03`, `DATA-04`, `DATA-05`, `MON-02`.
- **A9.** Уходит — доступ остаётся. → lifecycle-отзыв, полнота decommission. → `ACC-03`, `MON-03`.
- **A10.** Скомпрометирован → label-flip, сдвиг распределения. → статистика качества, lineage. → `DATA-02`.
- **A11.** Скомпрометированный serving-контейнер пишет напрямую в MLflow/MinIO. → per-service креды, netpolicy. → `RT-06`.

**Контур контроля и инфраструктура:**
- **A12.** Травит шаг пайплайна / базовый образ / захватывает раннер → гейты обходятся «легально». → пины образов, least-priv раннер, подписанный пайплайн. → `CI-01`.
- **A13.** Использует утёкший ключ/токен или реплеит сессию. → short-lived scoped-токены, ротация, аномалия. → `CRED-01`.
- **A14.** Пишет прямо в MLflow, меняет флаг `prod-approved`. → писать может только CP (netpolicy), integrity-проверка. → `REG-01`, `RT-06`.
- **A15.** Тащит вредоносную зависимость в саму платформу/сканеры. → пин+скан собственных зависимостей. → `SC-01`.
- **A16.** Через SSRF заставляет CP сходить к внутреннему сервису. → egress allow-list, нет user-controlled URL. → `ESC-01` (смежно).
- **A17.** Эксплуатирует баг авторизации → права MLSecOps / чужой объект. → object-level authz. → `ESC-01`.
- **A18.** Влияет на прод-данные, на которых модель дообучается. → provenance retrain-данных, дрейф. → `FB-01`.
- **A19.** Форсит деплой старой уязвимой версии. → version policy, запрет downgrade без аппрува. → `RB-01`.
- **A20.** Подменяет артефакт между сканом и загрузкой. → ре-верификация подписи при загрузке (admission). → `TOCTOU-01`.
- **A21.** Флудит инференс/обучение, жжёт ресурсы. → rate-limit, квоты. → `DOW-01`.
- **A22.** Заливает внешние поверхности объёмным флудом с тысяч источников; per-key rate-limit бесполезен, цель — обрушить доступность. → reverse-proxy перед периметром, global + per-IP rate-limit, лимиты соединений/размера/таймаутов, load-shedding (быстрый 503, защитить ядро), circuit breakers; объёмная L3/L4-защита (upstream scrubbing) — остаточный риск/допущение. → `DOS-01`.

## 3. Персоны защиты (RBAC-акторы)

|---|---|---|---|---|
| **D1** | «Страж» — MLSecOps | весь периметр | конфиг гейтов/политик, триаж findings, HITL, red-team/ART, runtime-защиты | Validate + Protect + видимость |
| **D2** | «Исследователь» — DS | свои модели | обучение, регистрация, запрос промоушена, model card, репродьюсибилити | Discover (вклад) |
| **D3** | «Конвейерщик» — DE | данные | приём, классификация sensitivity, lineage, качество | Secure data |
| **D4** | «Владелец» — Product / владелец модели | бизнес-риск | бизнес-критичность, согласование, чтение реестра | Governance |
| **D5** | «Капитан» — CEO / руководство | принятие риска | агрегированный статус защищённости | Visibility |
| **D6** | «Ревизор» — аудитор / комплаенс | соответствие | аудит-трейл, карта покрытия, MLBOM, воспроизводимость | Governance (read-only) |
| **D7** | «Пожарный» — Incident Responder / SOC | реакция | триаж сработок, IR-плейбук, **post-mortem**, корреляция событий | Detect & Respond |
| **D8** | «Хранитель» — Data Steward / владелец данных | данные как актив | владеет классификацией чувствительности и риском конкретного датасета | Governance (данные) |
| **D9** | «Смотритель» — Platform / SRE | сама платформа | доступность, секреты, сеть, бэкапы, изоляция сервисов | Self-security |
| **D10** | «Спарринг» — Red-teamer / attack-simulation | реальность защит | проактивно проигрывает сценарии атак (столп Validate как роль) | Validate |

## 4. Автоматические защитники (non-human controls)

Работают 24/7: **CI-гейт**, **admission-controller** (на деплое/загрузке), **runtime-детектор** (extraction/adversarial/drift), **hash-chain аудита**, **policy-engine** (fail-closed), **reverse-proxy / rate-limiter** (на периметре), **карта покрытия**. Именно они делают безопасность «фичей по умолчанию», а D7 («Пожарный») подключается, когда они срабатывают.

## 6. Редкие / edge-угрозы — остаточные риски и допущения

Сознательно вынесены за автоматизацию; ценность — показать, что подумали и приоритизировали:

- **Side-channel** (timing/cache) extraction — research-grade, вне скоупа.
- **Sponge / availability adversarial examples** — частный случай denial-of-wallet (`DOW-01`) и DDoS (`DOS-01`).
- **Объёмная L3/L4 DDoS-защита** (сетевой scrubbing, anti-DDoS провайдер) — вне ноутбука; на нашем уровне держим app-layer (`DOS-01`), сетевую защиту принимаем как допущение.
- **Стеганографическая эксфильтрация данных в весах модели** инсайдером — детект research-grade.
- **Компрометация хоста / docker-демона** — граница доверия (допущение: хост доверенный).
- **Evasion самих сканеров** («кто сторожит сторожей») — ShadowLogic это частный случай (`SUP-06`); смягчаем мульти-тулзами и валидацией.
- **Манипуляция слоем видимости** — подделать «зелёное» (триаж-в-FP без прав) → закрыто `VIS-04`.
- **Социнженерия HITL-аппрувера** (approval fatigue) — человеческий фактор, смягчается разделением полномочий и аудитом.

→ Полный перечень поведений — [bdd-catalog.md](bdd-catalog.md); оценка и приоритет — [risk-register.md](risk-register.md).
