# ADR-0010: Хранение секретов в HashiCorp Vault

- Статус: Accepted (реализовано, scoped)
- Дата: 2026-06-02

## Контекст
Секреты (signing-ключ, service-token, creds БД/MinIO/Redis/Keycloak, CI-вебхук) лежали в env/compose со слабыми дефолтами. Это антипаттерн: нет выдачи по правам, нет аудита доступа, нет быстрого отзыва/ротации. Для самозащиты контура контроля и по рекомендации куратора внедряем централизованный секрет-стор.

## Решение
1. **Vault** во внутренней сети (наружу не публикуется), как MLflow/MinIO.
2. **AppRole** для control-plane: `role_id` + `secret_id` выдаёт одноразовый `vault-init` на общий том, не «секрет-зеро» в env человека; control-plane логинится и получает короткоживущий токен (TTL).
3. **Политика least-privilege**: control-plane читает ТОЛЬКО свои пути (`secret/data/sirius/*`, `database/creds/sirius-cp`).
4. **Аудит**: включён audit-device — каждый доступ к секрету логируется.
5. **Что в Vault**: signing-seed и service-token (KV v2); creds БД через database-engine (dynamic secrets с TTL) — направление.
6. **revoke/rotate**: secret-id / токен / лиз отзываются мгновенно (тест: после `destroy` secret-id повторный AppRole-логин отклонён); ротация KV — новой версией.
7. **Фолбэк**: если Vault недоступен — control-plane стартует на env-секретах (fail-soft), Vault не становится единой точкой отказа control-plane.

## Scoped honestly
Vault в демо — **dev-режим** (auto-unseal, фиксированный root-токен, in-memory): воспроизводимо и показывает все фичи (AppRole, политики, аудит, revoke). Прод — **file/raft backend + auto-unseal (KMS/HSM)** + периодическая ротация secret-id и response-wrapping для доставки. Зафиксированное направление, не реализованное в окне.

## Последствия
- (+) секреты выдаются по правам, доступ аудируется, утёкший секрет отзывается мгновенно (закрывает CRED-02, усиливает ACC-03/CRED-01).
- (+) signing-ключ и service-token больше не «зашиты» в env как источник истины — Vault предпочтителен, env лишь фолбэк.
- (−) +2 контейнера (vault, vault-init) и операционная нагрузка (unseal, ротация) в проде; `secret_id` на томе — «секрет-зеро» сдвинут, не устранён (в проде — response-wrapping / платформенная identity).

## Альтернативы
- **Только env/compose-секреты** — просто, но без прав/аудита/отзыва; отклонено (антипаттерн).
- **SOPS / sealed-secrets** — шифрование секретов в git: решает хранение, но не динамическую выдачу, аудит и мгновенный отзыв; слабее для zero-trust-контура.
