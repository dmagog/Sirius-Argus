# ADR-0011: Интерактивная карта пайплайна (live-схема + drill в инциденты)

- Статус: Accepted
- Дата: 2026-06-04

## Контекст
Архитектура и пайплайн нарисованы в доках ([architecture.md](../architecture.md) §5/§7), но в работающем UI видимость — это таблицы (реестр, сработки, карта покрытия). Куратор грейдит видимость и интегрированность; разрыв «схема в доках ↔ таблицы в UI» ослабляет демонстрацию. Нужен экран, где пайплайн и проверяемые узлы видны пространственно, инциденты — на своих местах, с проваливанием.

## Решение
Отдельный экран `/map` («Пайплайн»): **гибрид** — верхний ряд пайплайна ЖЦ с гейтами + нижняя полоса инфра-узлов. Рендер — **bespoke SVG/HTML** (не Mermaid): узлы перекрашиваются по `id` из `/api/map/status` мелким JS-поллером без пересборки DOM (плавно, без мигания). Клик по узлу → drill в его сработки/аудит; клик по сработке → «инцидент» (окно аудит-таймлайна + угроза + реакция системы). Маппинг `Finding → узел` по `(tool, verdict, asset_type)`. Данные уже есть (`Finding`/`AuditEvent`/`Deployment`); новое — 3 эндпоинта + маппинг + рендер. Детали реализации — [docs/design/map-screen.md](../design/map-screen.md).

## Последствия
- (+) закрывает разрыв доки↔UI; money-shots (блок модели, extraction) видны как вспышка на схеме; пространственный двойник «Карты покрытия»; усиливает «видимость» и «интегрированность».
- (+) bespoke даёт плавный live без мигания и полный контроль drill-down.
- (−) больше кода, чем у Mermaid; схема дублирует docs-диаграмму — при изменении набора узлов держать в синхроне.

## Альтернативы
- **Mermaid** (переиспользовать схему доков) — консистентно и меньше кода, но `click`/перекраска фиддли, а ре-рендер при поллинге мигает. Отклонено в пользу плавности.
- **Ничего не делать** (оставить таблицы) — теряем сильный демо-экран и пространственную видимость. Отклонено.
