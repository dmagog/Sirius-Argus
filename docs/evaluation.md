# Проверяющему: запуск и сценарии

Стенд self-contained — поднимается одним `docker compose`, без внешних зависимостей. От `git clone` до рабочего UI и зелёных приёмочных тестов — минуты.

## Запуск

```bash
cp .env.example .env          # дефолтов хватает для оценки
DEV_AUTH=1 make up            # ядро: control-plane + Postgres + Keycloak + Redis + MinIO + MLflow + reverse-proxy
# или: DEV_AUTH=1 make up-full # + наблюдаемость (Loki/Grafana/Prometheus) + Gitea
```

`DEV_AUTH=1` включает локальные токены ролей вместо Keycloak — удобнее для прогона сценариев. В проде `DEV_AUTH=0`, authN через Keycloak (OIDC).

UI control-plane — **http://localhost:8080**. Сервинг моделей — **http://localhost:8001/models**. Grafana (full) — **http://localhost:3000**. Остановить — `make down`.

## Что делает демопрогон (`make demo`)

Один проход по money-shot'ам против поднятого стека; по каждому печатается результат. Что именно происходит:

| # | Сценарий | Вход | Реакция системы |
|---|---|---|---|
| 1 | Приём внешнего артефакта (`SUP-01`) | pickle с опасным `__reduce__` (`os.system`) | сканер (modelaudit + собственный genops) читает опкоды **не вызывая их**, классифицирует `malicious` → `422` + `Finding(critical)`; версия в реестр не попадает, `pickle.load` не выполняется |
| 2 | Скан зависимостей (`SUP-03`) | `requirements` с уязвимым пином (CVE) | `Finding`, красный чек на PR-гейте — версия не доходит до прода |
| 3 | Промоушен критичной модели (`VIS-03`, policy-матрица) | regulatory/financial-версия | проверяются модель-карта (`GOV-01`), воспроизводимость (`MON-02`), подпись (`SUP-04`), отсутствие открытых critical; промоушен — только после ручного аппрува **другим** MLSecOps (`ACC-02`), аппрув привязан к hash артефакта |
| 4 | Рантайм-extraction (`RT-01`) | бёрст запросов одного клиента к сервингу | троттлинг + `Finding`; петля runtime → control-plane |
| 7 | Принятие остаточного риска (`GOV-02`) | проваленный гейт + обоснование от старшей роли | conditional-деплой под условиями и сроком, всё в аудит |

Карта покрытия (`/coverage`, money-shot #5) показывает агрегат: угроза → контроль → live-статус на реальных `Finding`/аудите.

## Сквозной конвейер (`make pipeline`)

Один проход всего жизненного цикла одной модели: приём → скан → версия+lineage → policy-гейт → ручной аппрув-гейт → деплой → рантайм-атака → decommission. E2E-тест ассертит срабатывание каждого гейта.

## Приёмочные тесты (BDD)

```bash
cd tests && pip install -r requirements.txt && pytest -q     # 73 сценария против живого стека
```

Каждый `.feature` в `tests/features/` (Gherkin) — спека вида «угроза → что система обязана отработать»: блок / `Finding` / запись в аудит / объект не попал в реестр. Тесты гоняются против поднятого стека, не против моков.

## Тестовые фикстуры

Демо и тесты подают на гейты заранее заготовленные «плохие» входы — это тестовые данные, которые система должна отбить:

- pickle с `os.system` в `__reduce__` — сканируется по опкодам и блокируется до `pickle.load`; приёмочный тест проверяет отсутствие побочного эффекта;
- код с `os.system`/`eval` — для проверки ML-aware SAST (код не исполняется, анализируется AST);
- имена-тайпсквоты и dependency-confusion — для скана зависимостей.

Это входы для гейтов, а не исполняемая нагрузка.

## Проверить руками (zero-trust)

С `DEV_AUTH=1` действия идут под токеном `Authorization: Bearer dev:<user>:<role>` (роли `DS`, `DE`, `MLSecOps`, `Product`, `CEO`).

```bash
# действие вне роли → 403 + запись в аудит (DS не промоутит критичное)
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  -H "Authorization: Bearer dev:ds:DS" \
  http://localhost:8080/api/models/1/versions/1/promote          # → 403

# без токена → 401 (fail-closed)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/findings   # → 401

# несуществующий объект → 404
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/registry/model/9999999   # → 404
```

Ещё проверяемое:
- промоутить критичную модель без аппрува → блок; затем аппрув в UI как MLSecOps (`/map` → инспектор) → проходит;
- подменить запись аудита прямо в Postgres → БД-триггер отбивает `UPDATE`/`DELETE`, hash-chain рвётся, видно в `/health`;
- бёрст к сервингу → троттлинг + сработка; оверсайз-загрузка → `413`.

## Где увидеть доказательства

- **`/coverage`** и **`/api/coverage`** — статус контролей на live-данных.
- **`/dashboard`** — поток сработок и аудита в реальном времени.
- **`/health`** — целостность hash-chain аудита.
- **Grafana** (full-профиль, :3000) — метрики (счётчик сработок, целостность аудита, rate запросов по статусам) и логи; **Prometheus** скрейпит control-plane.

## Доступы по умолчанию

- UI control-plane — без отдельного логина (read-only витрины); чувствительные операции — через `/api/*` под токеном.
- Токены ролей при `DEV_AUTH=1`: `Bearer dev:<user>:<role>` (например `dev:alice:MLSecOps`).
- Grafana — `admin` / значение `GRAFANA_PASSWORD` из `.env`.
- Параметры и встраивание в свой контур — [integration.md](integration.md).
