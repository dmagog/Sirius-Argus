# Проверяющему: запуск и что потыкать

Стенд self-contained — поднимается одним `docker compose`, без внешних зависимостей. От `git clone` до рабочего UI и зелёных сценариев — минуты.

## Про «вредоносы» — спокойно

В билде нет реального вредоносного кода. Единственный «вредоносный» артефакт — демо-фикстура для money-shot #1: pickle, чей `__reduce__` возвращает `os.system("echo sirius-demo-marker")`. Что с ним происходит:

- он **никогда не десериализуется** — сканер читает опкоды (modelaudit + собственный genops), видит опасный `GLOBAL os.system` / `REDUCE`, возвращает `422` + `Finding(critical)`, в реестр артефакт не попадает;
- даже при исполнении это `echo` маркера, не RCE; приёмочный тест проверяет, что маркер-файл **не появился**.

То есть система этот артефакт ловит и блокирует — это и есть демонстрируемая фича.

## Запуск

```bash
cp .env.example .env          # дефолтов хватает для оценки
DEV_AUTH=1 make up            # ядро: control-plane + Postgres + Keycloak + Redis + MinIO + MLflow + reverse-proxy
# или: DEV_AUTH=1 make up-full # + наблюдаемость (Loki/Grafana/Prometheus) + Gitea
```

`DEV_AUTH=1` включает локальные токены ролей без Keycloak — так удобнее гонять сценарии. В проде `DEV_AUTH=0` и authN через Keycloak.

Открыть UI: **http://localhost:8080**. Сервинг моделей — **http://localhost:8001/models**. Grafana (full) — **http://localhost:3000**. Остановить: `make down`.

## Что потыкать в UI (http://localhost:8080)

| Раздел | Что посмотреть / сделать |
|---|---|
| `/map` — пайплайн | Карта ЖЦ, здоровье узлов. Кликнуть узел → инспектор прогона → для критичной версии **нажать «Аппрув»/«Отклонить»** и увидеть смену состояния — самый интерактивный момент |
| `/dashboard` | Live-поток сработок и таймлайн аудита |
| `/coverage` | CEO-вью: угроза → контроль → live-статус |
| `/registry`, `/data`, `/decisions`, `/users` | Реестры моделей/данных/решений/акторов + карточки сущностей (поиск, lineage, проблемы) |
| `/findings` | Единый список сработок с кликабельными активом и причастным |
| `/roles` | Матрица прав RBAC (роль → действие) |

## Сценарии: запустить и проверить

```bash
make demo        # money-shot'ы по живому стеку, печатает PASS по каждому:
                 #   #1 блок вредоносной модели · #2 уязвимая зависимость не доходит ·
                 #   #3 критичная модель только после ручного аппрува · #4 extraction-бёрст → троттлинг ·
                 #   #5 карта покрытия · #7 принятие остаточного риска под условиями
make pipeline    # сквозной ЖЦ одной модели: приём→скан→gate→аппрув-гейт→деплой→атака→decommission
make selfscan    # догфудинг SAST по собственному коду (bandit, 0 medium+)

cd tests && pip install -r requirements.txt && pytest -q   # 73 BDD-сценария зелёными против живого стека
```

Каждый `.feature` в `tests/features/` (Gherkin) читается как спека: угроза → что система обязана отработать. Это и есть «протестировать сценарии».

## Попробовать «сломать» (zero-trust в действии)

С `DEV_AUTH=1` действия идут под токеном `Authorization: Bearer dev:<user>:<role>` (роли: `DS`, `DE`, `MLSecOps`, `Product`, `CEO`).

```bash
# действие вне своей роли → 403 + запись в аудит (DS не промоутит критичное)
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  -H "Authorization: Bearer dev:ds:DS" \
  http://localhost:8080/api/models/1/versions/1/promote          # → 403

# без токена → 401 (fail-closed)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/findings   # → 401

# несуществующий объект → 404
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/registry/model/9999999   # → 404
```

Ещё проверяемое руками:
- залить вредоносный артефакт через ingest → `422` + `Finding` (см. money-shot #1);
- промоутить критичную модель без аппрува → блок; затем апрувнуть в UI как MLSecOps (`/map` → инспектор) → проходит;
- подменить запись аудита прямо в Postgres → БД-триггер отбивает `UPDATE`/`DELETE`, hash-chain рвётся, видно в `/health`;
- бёрст запросов к сервингу → троттлинг + сработка (extraction); оверсайз-загрузка → `413`.

## Где увидеть доказательства

- **`/coverage`** и **`/api/coverage`** — статус контролей на live-данных (что реально сработало/заблокировано в аудите).
- **`/dashboard`** — поток сработок и аудита в реальном времени.
- **`/health`** — целостность hash-chain аудита (`ok`/обнаружена подмена).
- **Grafana** (full-профиль, :3000) — метрики (счётчик сработок, целостность аудита, rate запросов по статусам) и логи; **Prometheus** скрейпит control-plane.

## Доступы по умолчанию

- UI control-plane — без отдельного логина (read-only витрины); чувствительные операции — через `/api/*` под токеном.
- Токены ролей при `DEV_AUTH=1`: `Bearer dev:<user>:<role>` (например `dev:alice:MLSecOps`).
- Grafana — `admin` / значение `GRAFANA_PASSWORD` из `.env`.
- Полный список параметров и интеграция в свой контур — [integration.md](integration.md).
